# Slides and speaker notes

Slide text is read in a glance while the user speaks. Speaker notes are read out loud, word for word.

## Slide text

- **Titles name the slide's point** in plain words. The same no-clever-headings rule applies.
- **Few words on a slide.** A phrase or a number beats a sentence. If the slide needs a paragraph, it belongs in the notes.
- **Label designed-only work** on the slide where the claim is made: never show a design as production practice.
- Visual style (fonts, colours, layouts) is in the `deck-style` skill, not here.

## Speaker notes

- **Write them as speech, in the first person.** Every word must be speakable as written.
- **No stage directions** ("Put the code up", "Land the title") and no lead-ins ("Let me ask you:"). If a line introduces a question, ask the question.
- **Delivery cues in asterisks:** *pause*, *slowly*.
- **Brackets only for time budgets** ([2 min]) and for Q&A triggers on backup slides.

## Workflow

Keep both gates from draft mode. At gate 2, show the slide titles in order with the planning note for each, instead of post headings.
