# What the user fixes, and why

Each pair is a line Claude drafted, the user's fix, and the reason. From the user's private corrections log. Only fixes that need judgement are here; anything a regex can catch is in `scripts/lint.py`. Add a pair when a new kind of fix shows up.

<pair>
<draft>I started as a newcomer, not an expert</draft>
<fix>I started at 2 cards a day</fix>
<why>A number says more than a contrast. "X, not Y" is a setup; state the X.</why>
</pair>

<pair>
<draft>Rules in prose became rules nobody can skip</draft>
<fix>Rules became checks</fix>
<why>Name the literal thing. "Nobody" is there for punch, and the repeated noun is a flourish.</why>
</pair>

<pair>
<draft>Run what can run in parallel</draft>
<fix>Run checks in parallel</fix>
<why>Plain word order over a clever echo. "I wouldn't sound like that."</why>
</pair>

<pair>
<draft>Fast checks run on every commit, evals once per deploy</draft>
<fix>Each check runs in one place</fix>
<why>One clause per heading. Two parallel clauses read as constructed.</why>
</pair>

<pair>
<draft>On a weak one, building the base is the work.</draft>
<fix>On a weak one, the base is where you invest first.</fix>
<why>"X is the work" is a compressed aphorism. Say the action the reader should take.</why>
</pair>

<pair>
<draft>explained that level again and asked a different question</draft>
<fix>explained that level again and asked a new set of questions</fix>
<why>Keep the size of what happened. Each quiz was a set of questions; don't shrink it to fit the sentence.</why>
</pair>

<pair>
<draft>The agent could read the whole repo in minutes. I couldn't.</draft>
<fix>The agent could read the whole repo in minutes but I couldn't.</fix>
<why>Join a short contrast with "but". A stand-alone "I couldn't." is a dramatic fragment.</why>
</pair>

<pair>
<draft>Everyone's a builder now</draft>
<fix>Effect of vibe coding</fix>
<why>A title names the topic plainly. Clever framing makes the reader decode it.</why>
</pair>

<pair>
<draft>...made later decisions quicker. There are ways to represent different modules of code as diagrams but at a certain point, having a rough map of key parts of the code in my head felt more useful to make key decisions.</draft>
<fix>Reading the code myself gave me a rough map of where things live. Module diagrams show some of that, but when I had to make a decision, the map in my head was more useful.</fix>
<why>Fold a new point into the sentence it extends. Don't repeat a content word ("key" twice) or use vague time ("at a certain point").</why>
</pair>

<pair>
<draft>Fast agents got expensive.</draft>
<fix>Fast agents get expensive fast.</fix>
<why>Present tense makes it a claim the reader can apply, not only the user's story.</why>
</pair>
